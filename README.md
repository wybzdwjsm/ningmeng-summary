# 柠檬总结

> 就地压缩 SillyTavern 上文聊天记录的扩展。压缩结果直接替换聊天消息——往上翻看到的就是压缩内容，发给模型的上下文同时变短。**不写世界书。**

## 和「总结到世界书」的插件有什么不同

| | 世界书类总结插件 | 柠檬总结 |
| --- | --- | --- |
| 结果放在哪 | 世界书条目，靠注入进入提示词 | 直接替换 `chat[i].mes` |
| 往上翻看到 | 原文（或被引擎隐藏） | 压缩后的记录 |
| 上下文体积 | 原文还在，额外再加一份总结 | 原文被替换，真实变短 |
| 生成时依赖 | 世界书扫描与注入 | 无额外注入 |

SillyTavern 构建 Chat Completions 提示词时只读取 `chat[i].mes`，而 `is_system` 消息会被过滤。因此压缩块被写成**普通角色消息**，一定会进入后续上下文；原文备份放在 `extra` 里，不进入提示词、不消耗 token。

## 功能

- **悬浮球**：右下角可拖拽，点一下打开插件面板；角标显示待压缩楼层数。ST 扩展设置里另有后备入口。
- **手动压缩**：输入任意起止楼层（0 起、含首尾），可设「每 N 楼压成一条」或「整段合并成一条」，支持中途停止。
- **自动检测**：达到设定阈值自动把靠前的旧楼层分段压缩，可设触发时机与「保留最近 K 楼不压缩」。
- **自选 API**：OpenAI Chat Completions 兼容；支持连接保存、测试连接、测试一次生成、加载模型列表、下拉选模型或手填模型名。
- **自动触发倒计时**：自动页实时显示「再增加 N 楼触发」，并区分已达标、冷却中剩余秒数、AI 生成中暂缓、自动压缩关闭四种状态。
- **破限词**：独立文本框，内容原样作为请求的第一条 system 消息发送，默认为空、不预置任何内容。
- **提示词预设**：内置三套压缩任务提示词（极简 / 均衡 / 详实）、可编辑的压缩块显示模板与二次压缩提示词。
- **自定义输出字数**：四种模式（不限制 / 按原文比例 / 每段固定字数 / 整次总字数自动均分），作为高优先级指令注入提示词，手动、自动、二次压缩统一生效；可预览本次每段目标字数，压缩日志会显示目标值与实际值。
- **请求节流 / 随机延迟**：所有生成请求之间至少间隔一段随机时间；批量压缩每段之间可设**固定停顿秒数**或随机区间，自动压缩触发也加抖动。单次请求超时默认 600 秒，长文本也能跑完。等待过程中可随时点「停止」，不会干等。
- **不放大正常聊天请求**：面板 token 统计改为纯本地估算（不再额外 POST tokenizers 接口）；自动压缩有冷却时间与单次段数上限，且在 AI 生成回复期间不启动。手动压缩不会被生成流程阻塞，随时可写入。
- **压缩块直接编辑**：压缩块旁的「编辑」按钮可直接改写真正进入上下文的那段文字，保存即写回聊天文件，不必还原重压。
- **压缩后自检**：每段压缩完成后自动追加一次请求，对照原文列出摘要**省略了什么**；结果存在压缩块里，点「自检」按钮查看，**不进入上下文、不浪费 token**。自检提示词与破甲词都在提示词页可改可恢复默认，自检失败不影响压缩结果。
- **原文查看与选择性还原**：压缩块旁有「原文」「全部还原」按钮；原文查看器默认只读、不改动聊天，可搜索、复制、勾选后只还原指定楼层，其余楼层继续压缩。
- **楼层预览**：面板「原文」页输入 `3`、`3-7`、`3,5,9` 即可只读预览压缩前的原文，再勾选还原。
- **备份与还原**：原文随聊天文件内联保存；压缩前自动存 IndexedDB 快照；支持导出完整备份、逐块/全部还原、重新载入聊天。
- **设置迁移**：导出 / 导入设置 JSON，跨设备带走 API 配置、破限词与全部提示词。
- **统计**：总楼层、压缩块数、上文字数、估算 token、累计省字。

## 安装

要求：SillyTavern 1.18 及以上（基于该版本 API 开发测试）。

1. 扩展（拼图图标）→ 右上角 **Install Extensions**
2. 粘贴仓库地址，例如 `https://github.com/wybzdwjsm/ningmeng-summary`
3. 确认第三方扩展警告 → 安装 → 打开开关 → **刷新页面**
4. 右下角出现悬浮球，扩展列表里显示「柠檬总结」

> GitHub 仓库名只允许 ASCII 字母、数字、`.`、`-`、`_`，不能用中文，推荐 `ningmeng-summary`。仓库叫什么不影响插件显示名——显示名由 `manifest.json` 的 `display_name` 决定。

手动安装：把仓库文件解压到 `public/scripts/extensions/third-party/<任意目录名>/`，刷新页面即可。目录名随意，资源路径基于模块自身 URL 解析；仓库 URL 也可以带 `.git` 或部署在反向代理子路径下。

> 注意：如果本地已经手动装过同名目录，再安装会提示目录已存在；换仓库名安装则会加载两份，记得关掉其中一份。

## 快速开始

1. 打开悬浮球 → **API** 页：填 API 基础 URL（如 `https://your-api.example/v1`）和密钥 → 保存 / 连接 → 加载模型列表 → 选择模型
2. **提示词** 页：按需粘贴破限词，选择压缩预设
3. **压缩** 页：选起止楼层和间隔 → 执行压缩
4. 需要自动化时去 **自动** 页打开开关并设阈值
5. 想回看细节：点压缩块上的「原文」，或在 **原文** 页输入楼层号预览

建议第一次压缩前先去 **备份** 页点一次「导出完整备份」。

## 数据存在哪里

| 数据 | 位置 | 是否跨设备 |
| --- | --- | --- |
| 插件代码 | GitHub 仓库 | 是，链接安装即可 |
| 压缩后的聊天记录与内联原文 | SillyTavern 服务端的聊天文件 | 是，同一 ST 服务 / 账号可见 |
| API 配置、破限词、提示词、面板参数 | 浏览器 localStorage | 否，用「导出 / 导入设置」迁移 |
| 自动快照 | 浏览器 IndexedDB | 否，换设备前导出完整备份 |

密钥只保存在本机浏览器，不会发往 SillyTavern 服务器；导出的完整备份不包含密钥，导出的设置文件**包含**密钥，请妥善保管。

## 常见问题

**测试连接报网络 / CORS 错误**：浏览器直连第三方 API 需要对方允许跨域。换用支持 CORS 的端点，或在「高级」页填自己的代理前缀。

**加载模型列表为空**：部分中转不提供 `/models`，直接在模型框手填模型名即可生效。

**推理模型返回空内容**：在「高级」页关闭 `temperature`、把 token 参数名改为 `max_completion_tokens`、调大最大输出 token。

**压缩后想看原文**：点压缩块上的「原文」，或在「原文」页输入楼层号；只读查看不会改变聊天记录。

**换设备后配置没了**：属预期行为，用「导出设置 / 导入设置」迁移。

**怕连续请求把 API 号搞封**：压缩页「请求节流」默认开启，生成请求之间会随机等待，批量压缩每段之间再额外等待，段数多时请求会被明显拉开。间隔、段间上下限都可调，还可以直接填「段间固定停顿」秒数（例如 30），每总结完一段固定停这么久；填 0 才用随机区间。段间等待中随时可点「停止」。模型列表等 GET 请求不受影响。

**长文本总超时失败 / 想让每段之间停更久**：高级页「请求超时」默认已提到 600 秒，旧配置里的 180 秒会在升级后自动改成 600，慢模型或长文本可继续调大。段间停顿在压缩页「请求节流」里填固定秒数即可。

**自检提示词和破甲词是什么**：破甲词只在自检请求里发送，作用是让模型严格挑错、不客套；自检提示词定义检查重点与输出格式。两段都在「提示词 → 压缩自检」里可改可恢复默认。自检每段多一次请求（同样受节流控制），失败不影响压缩结果；不想增加请求可在该页关闭。

**插件会不会让聊天请求变多**：面板 token 统计不再调用 ST 的 tokenizer 接口（旧版每次消息事件会多发一个 POST）；自动压缩默认冷却 120 秒、单次最多处理 3 段，且生成期间不启动。手动压缩不会被阻塞（v1.4.2 起取消了「等生成结束」的等待，避免看起来卡住）。如果你不用自动压缩，插件本身不会主动发任何请求。

**想让总结更短 / 更长**：压缩页「输出字数」里，选「按原文比例」填 `10` 就是压到原文的约 10%，或选「整次总字数」填 `800` 字（会按本次分段数均分）。建议保持「优先于提示词里自带的长度要求」开启，避免和预设里的篇幅描述冲突。点「预览本次目标」可以先看每段会被要求写多少字；目标较大时插件会自动抬高 `max_tokens` 防止结果被截断。

## 已知限制

- 部分还原后，压缩摘要里仍保留那些楼层的概览（模型输出没有「楼层 → 摘要行」映射，无法精确删除单行），上下文会有少量重复；要完全干净请选择「全部还原」。
- 在备份页清除过内联原文的压缩块不能逐层查看或还原，只能用快照整体恢复。
- 旧版本生成的压缩块没有逐条楼层号，会按压缩时的范围推算；若当时跳过了已有压缩块，个别楼层号可能有偏差。
- 压缩会改变聊天楼层编号，压缩过程中请勿切换角色或聊天（代码已加保护，检测到切换会放弃写入）。
- 输出字数是给模型的**软约束**，实际结果可能上下浮动；模型明显不听话时可降低 temperature 或换用指令遵循更好的模型。
- 开启请求节流后批量压缩总耗时会明显变长（例如 10 段、段间 5～15 秒，额外约 1～2 分钟），这是为避免触发上游风控的刻意取舍；不需要时可在压缩页关闭。
